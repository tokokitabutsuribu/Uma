# QR受付・ジュール数自動精算システム（2日間運用・ラウンド制対応版）

複数台の読み取り端末でQRコード（ID）をスキャンし、1台の管理デバイスでID・所持ジュール数（単位: J）をリアルタイムに集計するシステムです。さらに、5択の予想ゲーム（単勝／3連単）をラウンド制で開催し、結果に応じたジュール数の自動増減（精算）ができます。ラウンド中は別デバイスのWebカメラ映像を客画面にライブ表示できます。

## 基本の仕組み

- QRコードには**参加者のIDのみ**が含まれている想定です
- 初めてスキャンされたIDは自動登録され、**初期ジュール数1000J**が付与されます
- ジュール数は管理画面からいつでも運営が手動で書き換えられます（変更履歴も記録）
- 2日間通算で1つのジュール数として管理し、`data/store.json` に永続化されるためサーバー再起動後もデータは消えません

## ラウンド（予想ゲーム）の仕組み

0. **事前に「選択肢の設定」を決めておく**：管理画面の「ラウンド」タブ上部にある常設エリアで、5つの選択肢を設定します。ここで保存した内容は、変更しない限りどのラウンドでもずっと使われ続けます（ラウンドを開始するたびに聞かれることはありません）
1. **管理画面で「ラウンドを開始する」**：設定済みの5つの選択肢で、新しいラウンドが受付中になります
2. **参加者は読み取り端末でIDをスキャン**：受付中のラウンドがあれば、その場で「賭け方（単勝＝1つ選択／3連単＝順列3つ選択）」「賭け金（現在の所持ジュール数の一部）」を**参加者自身が**入力します
   - 送信と同時に、賭け金が所持ジュール数から差し引かれます（この時点で「参加登録」完了）
   - **同じIDでも、1ラウンドにつき最大2回まで**投票できます（賭け方や選択を変えて2回賭けることも可能）
3. **管理画面で「受付終了」**：ここで単勝・3連単それぞれのレート（倍率）が自動計算されます
   - レート = そのラウンドの賭け金合計 ÷ その選択肢に賭けられた金額の合計（競馬の払い戻しと同じ考え方）
   - **3連単は的中しにくいため、計算されたレートにさらに1.5倍の倍率をかけて高配当にしています**
   - 誰も賭けていない選択肢は「賭けなし」と表示されます
4. **管理画面で実際の結果（1〜3着）を入力し「精算」**：的中者にはレートに応じた配当が自動でジュール数に加算されます。この操作でラウンドは終了（精算済み）になります
5. **参加登録は精算と同時に消えます**：次にラウンドを開始すると、参加者はまた新しくスキャン・投票する必要があります（選択肢の設定はそのまま引き継がれます）

### レート計算・配当の例

- 単勝プール合計が3000点、選択肢「3」に500点賭けられていた場合 → レートは 3000 ÷ 500 = 6.0倍
- 「3」に100点賭けて的中した参加者は 100 × 6.0 = 600点を獲得（差し引き +500点）
- 3連単プール合計が2000点、「3→1→5」の順列に100点賭けられていた場合 → 通常のレートは 2000 ÷ 100 = 20.0倍だが、1.5倍の割増で **30.0倍** になる
- 外れた投票は、その時点で差し引かれた賭け金がそのまま戻ってきません（追加の減点はありません）
- 誰も的中しなかった場合、そのプールの配当はありません（賭け金は運営側の持ち出しにはなりません）

## 構成

- `server.js` … 中継サーバー（Node.js + Express + Socket.io、ラウンド・精算・カメラ映像中継ロジックを含む）
- `public/scan.html` … 読み取り端末用ページ（ID読取＋ラウンド中はその場で賭け入力）
- `public/admin.html` … 管理デバイス用ページ（ラウンド管理／参加者・ジュール数／スキャン履歴／ジュール数変更履歴の4タブ）
- `public/camera.html` … カメラ送信端末用ページ（Webカメラの映像を客画面へライブ配信）
- `public/public.html` … 客画面用ページ（ラウンド受付中はカメラ映像、それ以外は結果ボードを自動表示）
- `data/store.json` … 自動生成されるデータファイル

## セットアップ手順

### 1. サーバーPCの準備

```bash
cd qr-checkin
npm install
npm start
```

起動ログに表示されるURLに、同じWi-Fi内の各端末からアクセスします。

```
読み取り端末用: https://192.168.1.23:3000/scan.html
管理デバイス用: https://192.168.1.23:3000/admin.html
カメラ送信端末用: https://192.168.1.23:3000/camera.html
客画面用: https://192.168.1.23:3000/public.html
```

**カメラ機能（QR読み取り）はHTTPSでないと動作しないブラウザが多いため、このシステムは自己署名証明書で自動的にHTTPS化されています。** 各端末で初回アクセス時に「保護されていません」「この接続ではプライバシーが保護されません」といった警告が表示されますが、これは自己署名証明書（無料の証明書を自動生成しているため、公的な認証局の証明ではない）によるもので、同一LAN内での利用であれば問題ありません。警告画面で「詳細」→「〇〇にアクセスする（安全ではありません）」のような項目を選んで進んでください（1端末につき初回の1回のみ）。証明書は`data/cert.pem`・`data/key.pem`に保存され、サーバーを再起動しても同じものが使われます（毎回警告をやり直す必要はありません）。

### 2. 運営（管理デバイス）の操作

`admin.html` を開くと、デフォルトで「ラウンド」タブが表示されます。

1. 「操作者名」を入力しておく（ジュール数変更履歴に記録されます）
2. （初回のみ、または選択肢を変える時）上部の「選択肢の設定」で5つの選択肢を入力し「この内容で保存する」
3. 「ラウンドを開始する」（保存済みの選択肢がそのまま使われます）
4. 参加者のスキャン・投票が出そろったら「受付終了してレートを確定する」→ 単勝・3連単のレート表が表示されます（3連単は自動で1.5倍の割増レートになっています）
5. 実際の結果（1着・2着・3着）を選んで「結果を確定して精算する」→ 自動でジュール数が増減し、精算結果と過去のラウンド履歴に記録されます
6. 続けて次のラウンドを開始できます（選択肢の設定はそのまま引き継がれます）

参加者・ジュール数タブ、スキャン履歴タブ、ジュール数変更履歴タブは従来通り確認・編集・CSV書き出しができます（ジュール数変更履歴には手動編集・賭け金の差し引き・配当のすべてが記録されます）。

### 3. 参加者・読み取り端末での操作

1. `scan.html` を開き、端末名を入力してカメラを許可
2. QRコード（ID）をスキャン
3. **ラウンドが受付中の場合**：その場で賭け方（単勝／3連単）・予想・賭け金を選んで「この内容で確定する」
   - 3連単は、選択肢を1着→2着→3着の順にタップします（もう一度タップすると選択解除）
   - 賭け金はクイックボタン（10%／25%／50%／全額）か直接入力で指定します
   - **同じIDで、1ラウンドにつき最大2回まで**賭けられます。1回目の投票完了後に「もう1回賭ける」を選ぶと、続けて2回目を入力できます
4. すでに2回投票済みのIDを再スキャンした場合は、これまでの投票内容が確認表示されます
5. ラウンドが受付中でない場合は、通常のID・所持ジュール数確認のみ表示されます

### 4. カメラ送信端末での操作

Webカメラ付きのPCやスマホ・タブレットを用意し、`camera.html` を開きます。**最大2台まで同時接続でき、客画面では2台分の映像が画面分割（左右）で表示されます**（1台だけの場合は全画面表示）。

1. プルダウンで使用するカメラを選ぶ（複数カメラがある場合）
2. 「カメラを起動して送信開始」を押す
3. 以降、このカメラの映像が客画面（`public.html`）にライブ配信されます（1台目・2台目の順に接続した方から順にスロット1・スロット2に割り当てられます）
4. 送信中はこのページを閉じたり、端末をスリープさせたりしないでください
5. 既に2台接続されている状態で3台目が接続しようとすると、「カメラは既に2台接続されています」と表示され、送信は開始されません。1台切断されるまで待つか、不要な方を切断してください

### 5. 客画面（お客様向け表示）

プロジェクターやモニターにつないだ端末で `public.html` を開いておきます。

- **ラウンドが受付中（開始直後）になると、自動でカメラ映像に切り替わります**
- それ以外（受付終了後〜次のラウンド開始前）は、以下を表示する結果ボードになります
  - 現在のレート（直近に受付終了したラウンドの単勝・3連単レート）
  - 選択肢ごとの着順回数（これまでの全ラウンドを集計した1着・2着・3着の回数）
  - 前ラウンドの勝者全員のID
- カメラが未接続の間は「カメラ映像を準備中です…」と表示されます
- この自動切り替えは、`admin.html`の「ラウンド」タブ上部にある「客画面コントロール」から、いつでも「カメラ表示に固定」「結果ボード表示に固定」に手動で上書きできます。運営の意図に合わせて自由に使ってください（「自動」に戻せば従来通りラウンド連動になります）

## 2日間運用のヒント

- サーバーは同じPCで動かし続けるのが基本です。シャットダウンしても `data/store.json` にデータが残るので、翌日 `npm start` すれば続きから再開できます
- 念のため、1日目の終わりに `data/store.json` をコピーして別の場所にバックアップしておくと安全です
- サーバーPCのIPアドレスが変わると各端末がアクセスできなくなるため、ルーターで固定IPにするか、2日目の朝にIPアドレスを再確認してください
- 「全データ初期化」ボタンは参加者・ジュール数・全履歴・ラウンドを完全に削除します。**本番開始前のテストのみ**に使い、運用中は使用しないでください

## カスタマイズのヒント

- **賭け金の上限（例：1回の上限は現在の所持ジュール数の50%まで）**を設けたい場合は、`server.js` の `place-bet` ハンドラにバリデーションを追加してください
- **レート算出方式**（現在は控除なしのシンプルな按分方式に、3連単のみ1.5倍の割増）を変更したい場合は、`close-round` ハンドラ内のレート計算部分（`TRIFECTA_RATE_MULTIPLIER`）を調整してください
- **ラウンドの選択肢数**は現在5つ固定です。変更する場合は `server.js` の `CHOICE_COUNT` と、`scan.html`／`admin.html`／`public.html` の関連UI（グリッドやセレクトボックス）を合わせて調整してください
- **カメラ映像が繋がらない場合**：カメラ送信端末と客画面が同一LAN内にあるか確認してください（現在の実装はSTUN/TURNサーバーを使わないため、異なるネットワーク間や複雑なファイアウォール環境では接続できないことがあります）

## 動作確認済み環境

- Node.js v18以上
- Chrome / Safari（モバイル）
- 同一Wi-Fiルーター配下の複数端末
